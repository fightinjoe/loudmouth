# Design: Conversation-first phrasebook

Generated by /office-hours on 2026-09-03. Reviewed by /plan-eng-review on 2026-09-03.
Branch: api_improvements
Repo: fightinjoe/loudmouth
Status: APPROVED
Mode: Builder

## Goal

The `/textbook` prompt now writes much better content because it designs a real conversation first
and draws the phrases and words out of it. But that conversation ends up buried as the last group,
and the app is built around individual groups of cards. We want the conversation to be the thing the
learner sees and studies.

Real prep conversations also branch — a doctor visit prepared around cold symptoms can turn to diet,
work stress, or sleep — so one canonical dialogue is the wrong shape. The pivot: generate **several
short conversations** for a situation instead of one, and put them front and center, with vocabulary
and starred cards alongside.

## What the current prompt does

`/textbook` runs two prompts:

1. **Questions prompt** — returns clarifying `questions` and a `checklist` of suggested communicative
   goals, each `{ label, checked }`.
2. **Generate prompt** — designs one canonical two-sided conversation, derives themed teaching groups
   from it, adds a "Words for this exchange" group, and emits the dialogue last as a single "Example
   conversation" group. Returns `{ title, groups }`, where each group is `{ title, cards }` and every
   card has a `type` of `word` or `phrase`.

So today: one conversation, buried; content organized as themed groups.

## What changes

Only the two prompts change. The response stays `{ title, groups }`.

1. **Questions prompt** — the `checklist` becomes the list of **conversation titles** for the
   situation: the scenes to prep, in before/during/after order, goal-revealing where possible (e.g.
   "Compliments and offering help", "During the meal", "Saying goodnight"). The learner checks which
   ones to generate.

2. **Generate prompt** — for each checked title, write **one short conversation**: a 3–8 turn (target
   6) two-sided dialogue, distinct from the others, in timeline order. Each conversation is a group of
   `phrase` cards with the speaker in `notes` (`{"speaker":"you"}` / `{"speaker":"partner"}`) — the
   same way today's "Example conversation" group already works, just several of them. Then pull the
   highest-value situation words into `word` cards (nouns, adjectives, verbs; verbs in dictionary
   form), gathered in a single **`vocab` group**, each card noting in `notes` the phrase it came from.

Nothing else about a card changes.

## How the app shows it

Three tabs, built from the cards the prompt already returns:

- **Conversations** — the conversation groups (the `phrase` dialogues), in order.
- **Vocab** — the `word` cards, which the prompt returns as a single `vocab` group.
- **Starred** — any card the learner has starred, treated the same regardless of which tab it came
  from (a card is a card). Review runs only on starred cards.

The tabs are a way of displaying the cards already returned, split by `type` and group. No change to
storage, the card schema, or the response shape.

## Why this is a small change

- The response is still `{ title, groups }`, so the web app (which already renders groups) and the
  iOS app both keep working — a prompt change doesn't touch them.
- Same cards, same `context`, same IndexedDB — no data migration.
- No fan-out needed: the budget probe (`api/evals/eval-budget.js`) showed google generates ~6
  conversations in one call in about 10 seconds, cheaply.

## Decisions (settled)

- **google** is the backend we build and tune for; the other adapters stay for quality benchmarking.
- **~6 conversations** per phrasebook, at least 3; each conversation is 3–8 turns (target 6).
- Generation takes ~8–10 seconds — treat it as a one-time create with a loading state.
- **Web first**; an iOS conversation view is a later follow-up.
- Keep conversations distinct: fold a yes/no pair (ask → accept … ask again → decline) into one
  conversation rather than making two near-duplicates.

## Review

`/plan-eng-review` (2026-09-03), with a Codex second opinion, confirmed the direction. Under the
"prompt-only, keep `groups`" framing above, the earlier worries about a new response shape, client
breakage, storage migration, and iOS work don't apply. Two small things to keep in mind: run the eval
as a quality check on the new prompt, and note that the web import loop in `web/app/src/js/db.js`
isn't transactional — a pre-existing bug worth fixing, but not part of this change.

# Catchphrase interaction design

> **Naming.** **Catchphrase** is the product name; code identifiers and infrastructure use the code name `loudmouth`. The collection noun is **phrasebook** (one word). This page describes the web client; native iOS state is in [iOS architecture](ios/architecture.md).

The product is organized around one prep-first loop: create a complete phrasebook for a situation, star the cards worth emphasizing, and review those cards. Successful generation commits the complete phrasebook at once.

## Information architecture

The web app follows the [Pane Protocol](web/pane-protocol.html). The stage has four fixed layers, from bottom to top: **shell**, **content**, **details**, and **action**.

- **Navigation pane** (shell) — always present. It contains the illustrated landing page, complete phrasebook library shelves, language-grouped navigation, and the new-phrasebook entry point. Opening library navigation reveals it.
- **Content pane** (content) — shows the selected phrasebook or a browse list. Changing content swaps this pane's screen rather than adding a layer. A phrasebook's **chapter sheet** is a modal surface inside the content pane, not a separate layer: it covers the landing and keeps the details and action layers above it.
- **Details pane** (details) — an expanding phrase-card modal over a scrim on web. It explains one phrase and returns to the original card and content scroll position when dismissed.
- **Action pane** (action) — an optional modal bottom sheet over a scrim. Its kinds are guided **creation** (including language selection), **review**, phrasebook **settings**, and **json** export (opened from settings). At most one action pane is open.

A pane's component name identifies its fixed layer and behavior; its content name identifies what it currently renders. For example, **creation** and **review** are content modes hosted by the same action pane, not separate pane components.

## Navigation pane

The web navigation uses an illustrated-paper direction: a fixed foreground speech-bubble title, slab typography, contextual artwork, and quiet reading surfaces. Catchphrase is a personal language textbook for preparation and learning, not live translation.

First use offers **New phrasebook** and clickable example situations. Examples move slowly, pause for focus, hover, touch, or manual scrolling, and stay static under reduced motion. Selecting an example seeds the real creation flow; it does not generate or save automatically. Returning users see every retained phrasebook in a two-row horizontal shelf, ordered by most recent access/creation, plus language-grouped navigation and a separate creation action. Counts describe unique saved cards. Ready illustrations belong to their actual phrasebooks; missing, failed, and pending artwork uses neutral frog paper. Language browsing has no inferred star state; starring and Review always require a phrasebook.

Selecting a phrasebook opens its content pane. Language browsing retains every card type.

## Guided creation

**New phrasebook** opens the full-height **Creation** action pane directly. Its design is [Figma section 1304:33600](https://www.figma.com/design/sn5VMavDDp38gSwsRVRhcS/CatchPhrase?node-id=1304-33600). The header holds Back, the phrasebook language as a centered dropdown, and a clear button that appears once text is typed. Below it the learner types the situation in a large field whose placeholder asks "What are you preparing for?"; a round submit button appears with text, and Enter submits. A **Suggestions** list of five example situations (`CREATION_SUGGESTIONS` in `web/app/src/components/creation-panel.ts`) follows; choosing one enters it in the field and submits it.

The language is, in order: the language passed by the entry point, the last confirmed creation language, or the newest saved phrasebook's language. With none of these (first run), the pane opens with the dropdown expanded and Japanese selected. Tapping the dropdown grows the picker out of the dropdown's own footprint; choosing a language closes it and is remembered in this browser independently of phrasebook saving, as is the language of a submitted situation. An outside tap or Escape closes the picker unchanged, and that tap does not also activate what it landed on. The language can change only while the situation is editable and is immutable after the phrasebook is saved. The picker lists `CONTENT_LANGUAGES` from `web/app/src/js/lang.ts` alphabetically; the Figma picker's separate Spanish variants are a [backlog todo](todo/backlog/spanish-variants.md).

The pane is gray with one white backdrop behind the current area of focus. The backdrop is a separate element from the content: first it sits behind the header and situation field, then behind the waiting message ("Thinking about the situation…" while `/context` runs, "Building your phrasebook…" after **Create**), then behind each question card. On every step change it animates its position and height to the next area, and the new content fades in; reduced motion skips both. After submission the situation stays at the top as fixed text and the dropdown chevron disappears. Questions and the topic checklist are cards with the question as title, rows with circular radio or check indicators, and **Back** with **Next** or **Create** at the bottom. The whole pane scrolls, and swiping down from the header dismisses it. A seeded example survives first-run language selection and later language changes.

The creation mode is a linear flow:

```text
situation (language dropdown, suggestions) → thinking → questions (ability first when unknown) → topic checklist (generation runs) → building → phrasebook
```

Topic submission calls `/context` with `{ seed, language, ability? }` (using the remembered ability for this language when available) and independently starts `/phrasebook-title` with `{ seed }`. If ability is unknown, the client prepends "What is your language ability?" to the returned questions, with options None, Basic, Conversational (stored as `none`, `basics`, `conversational`). This client-owned question is outside the model's five-question cap; the model is instructed not to ask proficiency questions. On web, each question occupies its own card, and every question uses the same grouped-row radio component with circular indicators. Clicking a radio only selects it; **Next** advances. Context questions start unselected. Generated questions end with an Other radio and a text box whose placeholder is "Other"; typing selects it, and Next or Enter submits nonblank, trimmed text. Ability retains only its three supported choices. Back and Next preserve answers, with Next disabled until the current question has an answer. Completing the last question starts `/phrasebook` with `{ seed, language, ability, answers, checklist }`, using the selected or remembered enum value and copied flat `answers` excluding the ability question. `checklist` contains all suggested labels in order; local topic selection starts from the model's checked defaults. Under **Which topics should be included?** the learner selects 1–8 topics locally while generation runs; toggling topics never sends another request and model selection remains server-owned.

The parallel naming request never blocks advancing or saving. Immediately before creating the local phrasebook, the client freezes the available generated title or falls back to the original seed. Pending title work is aborted and late responses are ignored; naming errors remain silent. The title becomes the local phrasebook name and is not sent to `/phrasebook`. Answer changes and card-generation retries reuse it. A different seed replaces the naming request; dismissal aborts it. A failed local save retains the frozen title on retry.

No phrasebook data is persisted while answering questions or selecting topics, even if generation has finished; the confirmed language preference is independent. **Create** validates the whole v4 draft, retains selected topics by original index, and atomically saves their sections and Word placements. Exact-English repeated Things to say belongs to the earliest retained topic; unchecked topics cannot suppress it. Every exchange response, example line and Word-family placement remains, including repeated Words across topics. There is no global word cap or duplicate text request. **Create** reuses pending or ready work; finishing speculative generation alone never saves or navigates. Back without changes reuses work; answer or seed changes invalidate and abort text work. Choosing another language preserves the prompt but clears context, answers, and checklist, aborts speculative work, and resolves remembered ability for the new language. Request-identity guards ignore stale responses. Confirmation shows the loading state for at least 1000 ms before saving and displaying the phrasebook, configured by `PHRASEBOOK_MIN_LOADING_MS` in `web/app/src/components/creation-panel.ts`. This minimum overlaps any remaining generation time rather than adding a delay after generation. Back while `/context` is pending aborts it and returns to the editable situation; Back while building dismisses the pane. Background failure leaves the checklist usable until **Create** surfaces it; retry preserves choices and starts fresh text work. Dismissal aborts text requests and discards uncommitted results. Incomplete saves are rolled back.

Context completion starts independent seed-based cover work. Answer/checklist changes reuse it; a new seed or dismissal before commit cancels it. Atomic text commit binds the request identity to the saved phrasebook, after which closing creation does not cancel it. A late result updates only that book's illustration and visible artwork, without remounting cards or resetting chapter, tab, scroll, focus, or reorder state. Failed art is nonfatal. Reload marks interrupted pending art failed without automatically restarting paid work.

Ability is saved as phrasebook metadata and remembered per language only after generation and import succeed on **Create**. Failed saves and abandoned speculative results do not remember it. Future creation skips this question and sends the remembered value to both endpoints. Updating it is deferred. Historical setup preferences are not inferred or migrated to the new scale.

Speculation hides generation behind checklist interaction but does not guarantee lower latency: English generation uses bounded per-topic concurrency, and the response waits for every translation, including topics later discarded. Usage includes all generated topics, so the meaningful measures are **Create**-to-usable-phrasebook time and cost per saved phrasebook. Durable transaction and cancellation boundaries remain authoritative in [the shared card schema](card-schema.md#atomic-lifecycle). Production state is in [API operations](api/operations.md#production).

## Phrasebook view

The design record is `explorations/phrasebook-organization/PHRASEBOOK_ORGANIZATION.html` (iteration 6, "Organized by category"). A web phrasebook opens on a vertically scrolling **landing** of category cards; each category opens in a **chapter sheet** that gathers that category from every topic. This supersedes the iteration 5 topic decks, which gave each topic its own landing card and tabbed sheet.

The fixed title layer starts as a speech-bubble title over the illustration, with Library on the left and Settings on the right. Once the landing scrolls past 150 px the bubble gives way to a slim single-line title bar; it returns below 110 px, so small scrolls near the threshold do not flicker. The illustration and the target-language pill scroll with the content; the white reading surface starts beneath the illustration.

The landing lists, in order: a **Starred** card when the phrasebook has stars (absent at zero), one card per category with content — **Words**, **Key phrases**, **Exchanges**, **Conversation** — then supplemental **Translations**, **Words**, and **Chunks** cards when unplaced entries exist. A category card has a header (glyph, category title with its count, **Open**) and one horizontally snapping row of deck cards. Words counts word-family groups and Exchanges counts exchanges; their deck cards are headed by the family or exchange title and clustered per topic. Key phrases and Conversation count topics and have one deck card per topic, headed by the topic title; Conversation cards preview the first lines as speaker-aligned bubbles. Topics follow stored Group position and are identified by Group ID even when titles duplicate. Each deck card previews its first item with English and a count; empty families, exchanges and topic sections are omitted, and a category with no content has no card. Touch scrolls the row natively; desktop mouse drag and focused Arrow/Home/End keys also move it. The Starred card groups starred Words by family title and starred Phrases and Chunks under **Phrases**. Deck cards are previews: labels, first item and count truncate to one line and English to three; category names wrap to two lines. Full text is in the chapter sheet, where card text wraps.

A category header opens its chapter at the top; a deck card opens the same chapter scrolled to that family, exchange or topic section, briefly highlighting an exchange. The sheet is modal: the landing, title layer, and Review tray become inert; Back, the scrim, or Escape close it and return focus to the opener. Its title is a **chapter menu** listing Starred (only when stars exist), the categories with content (the current chapter is always listed), then the supplemental collections; picking an item replaces the content. Arrow/Home/End move within the menu, and Escape closes the menu before the sheet.

A category chapter is one vertical page without tabs covering every topic. Words sections are headed by family and Exchanges sections by exchange title, each with its topic named underneath; Key phrases and Conversation sections are headed by topic. Section headings stay pinned while their section scrolls. Supplemental collections show one list without tabs. A category without content shows a short empty message.

Exchanges read vertically: learner turns sit left on gray, partner turns right on white with a border. Explicit response options inside one turn are separated by “or”; “or” never appears between adjacent example lines or is inferred from matching speakers. Example conversation is linear, one phrase per speaker turn. Each Phrase occurrence supplies its own translation, topic, section, and local position; exchange options also retain exchange ID and turn index. Repeated occurrences may share a durable Phrase without sharing presentation state. Exact-English cross-topic Things to say duplicates are removed at commit; empty sections are omitted. Every Word-family placement remains even when the canonical Word is shared across topics. Exchange and family titles, IDs and order are durable. Topic Word placements are not copied into supplemental Words.

The **Starred** sheet has **Words** and **Phrases** tabs over a horizontally snapping pager; tapping a tab, Arrow keys on the tabs, or swiping the pager changes tab. The Starred tab is remembered for the current phrasebook during the session and resets when another phrasebook is selected. Starred contains each starred membership once in saved entry order, the same order as Review; repeated Phrases use their first saved occurrence and translation. Each row shows its context (topic and Word family) and an **In context ›** link that opens the entry's category chapter and highlights the row. The landing's **Review starred cards** tray is available on stored phrasebooks and disabled when there are no stars.

Saving a whole exchange as one review item is not implemented; the exploration records it only as a schema proposal, and stars remain per card.

Ready saved artwork fills the masked header illustration without repeating; existing saved images are reused without automatic regeneration. The unchanged API generates a 16:9 watercolor cover, not a seamless tiled pattern. Missing, pending, and failed artwork uses the repeating static frog paper. Ready completion changes only the illustration and library thumbnail, without remounting cards or resetting scroll, focus, or reorder.

Phrasebook color comes from `--phrasebook-*` tokens in `web/app/src/styles/textbook.css`, all derived from one `--phrasebook-accent`. No per-phrasebook accent is persisted yet, so every phrasebook uses the default green.

Typography uses Hepta Slab titles, Roboto Condensed section labels, and Manrope language cards. Target language and any reading precede English. Japanese displays script with available furigana or romaji according to the phrasebook reading setting; absent romaji retains script. Chinese pinyin remains ruby-aligned. Word definitions remain smaller optional teaching text. Chunk cards show the full immutable source with its saved span highlighted.

Stars are independent 44px targets and update every occurrence of a membership without changing another phrasebook. Unstarring keeps the saved card, membership, and evidence. Live counts are announced; removing a focused Starred row moves focus to the next remaining star or the sheet's Back button rather than losing it.

Cards can be starred for review when they have a membership in the active phrasebook. Landing deck cards only open the sheet; card rows in the sheet or language browse speak on tap: Phrases use their pronunciation, Words their dictionary headword, and Chunks the full preserved source snapshot. Phrase breakdown opens on a 500 ms long press, right-click, or Shift+F10/Context Menu key while the card is focused. Movement, scrolling, cancellation, or navigation cancels the hold; its release never also plays audio. Stars remain independent tap targets. There is no card speaker icon or visible Explore phrase link.

**Reorder cards** is a control in the chapter sheet header of a stored phrasebook while a category or supplemental collection is open; Starred has no reorder. **Done** saves and **Cancel** restores; closing the sheet leaves reorder without saving. Reordering stays within one topic's Key phrases (Things to say) or Example conversation section, within a single exchange turn's options, or within a single Word family. It updates placements or occurrences, never canonical card identity, exchange/turn ownership or family ownership. Card-content editing and its swipe edit/delete actions are removed from the web app; card taps do not open an editor. Phrasebook settings, including naming, open from the title layer's Settings button. Source details and language browsing remain available; language-wide browsing is a plain list with no chapter sheet and no star/review controls without a phrasebook.

Physical-device thumb reach, VoiceOver, and iOS Safari gesture behavior require their own checks. Very long titles with enlarged text remain a hierarchy stress case. A new situation starts guided creation from navigation rather than extending an existing phrasebook.

## Phrase breakdown (web)

The reference is `explorations/phrase-breakdown/PHRASE_BREAKDOWN.html`. The existing details layer hosts the expanding-card interaction; it is not a fifth layer or an action-pane mode. A geometric copy grows from the card over 400 ms without scaling text. The original row stays in place but hidden, preserving conversation geometry and scroll. Closing reverses to it. Reduced motion skips animation. The modal has 12 px side margins within the 480 px app width, 36 px vertical margins, and 20 px corners. Close remains bottom-right while the body scrolls.

English precedes the source phrase; ruby stays above the characters. Japanese reading mode does not also show romaji. Selecting a semantic chunk shows its contextual English meaning, exact source fragment with available readings, role, and explanation. Selected text, underline, and explanation share blue emphasis. **SHOW ALL** highlights every chunk and displays explanations in source order; **SHOW SELECTED** restores the last individual selection. Selecting a chunk exits all-mode. The count and toggle follow the explanations; a single-part phrase has no toggle. Reopening resets selection and detail scroll. Each API chunk displays its nested dictionary-form Words and exactly one primary target: either an equivalent Word or a distinct contextual Chunk. Candidate controls resolve the current phrasebook's durable membership state when details opens and after every toggle; the analysis cache never supplies card IDs or star state. With no active phrasebook, analysis remains available but save controls are unavailable.

Opening calls `/phrase-breakdown` with the exact occurrence snapshot, source references, and only the active phrasebook context. The source remains visible during loading and errors; **Retry** makes a new request after failure. **Regenerate** bypasses the cache while retaining the current analysis if the new request fails. Valid teaching and candidates are cached in tab-scoped sessionStorage under `loudmouth-topic-v4.phrase-breakdown.v1:` plus the serialized exact versioned request, including refs, context, and readings. Invalid entries, including older responses without `flags`, are removed. Editing the request source or context therefore cannot reuse stale analysis. Opening, closing, retrying, regenerating, and cache clearing make no durable library writes; only an explicit successful star action saves or reuses a card and membership. Ready/reopened targets resolve stars from IndexedDB, not cached analysis. Regenerate never overwrites saved teaching. Closing aborts the client request and suppresses stale UI updates, not an already committed star. Atomic starring and Word-evidence persistence follow [the shared card schema](card-schema.md#atomic-lifecycle).

The conversation is inert while details is open. Focus enters Close; Tab stays within the modal. Close, Escape, or the scrim dismiss and restore focus to the original card without scrolling. Opening an action pane or navigating/replacing content releases details immediately, without a delayed focus restoration that could interrupt the next pane. There is no sibling traversal or drag-to-dismiss in this variant.

## Review

Review is a full-height action-pane mode opened from the **Review starred cards** tray on a stored phrasebook's landing. Its study set contains one joined entry per starred membership in saved entry order, the same order as the Starred sheet; a repeated Phrase uses that phrasebook's first occurrence. Default order preserves that list, while the saved reverse or random setting is applied once when the review session opens. With no starred memberships, the tray's action is disabled.

Each target keeps its own review contract:

- A **Phrase** uses the chosen occurrence's translation, so a shared Phrase in another phrasebook cannot change its interpretation.
- A **Word** presents its dictionary headword, own reading, and sense translation as the primary target. After reveal, a collapsible **Source examples** section shows full preserved snapshots with the encountered span highlighted and the historical source translation. Current-phrasebook examples come first, followed by the remaining examples chronologically. No evidence means no source section.
- A **Chunk** always uses its full original-script source snapshot. English-to-target shows the contextual gloss and masks only the selected span with a constant blank; reveal restores and highlights it without leaking ruby from a partially cut reading token. Target-to-English highlights the span immediately but keeps the gloss hidden until reveal. Role, explanation, and full source translation appear after reveal, and audio speaks the full source phrase rather than the fragment.

All targets support a session-only direction toggle, hidden-answer reveal, press-and-hold peek, direction-independent target audio, and left/right swipe navigation. Changing direction or moving to another entry hides the answer again. Review does not loop and has no end-of-deck summary: navigation stops at the first and last entry. Closing returns to the same phrasebook. Source snapshots remain usable after their parent Phrase, occurrence, or phrasebook is edited or deleted.

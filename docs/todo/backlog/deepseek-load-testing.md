# Load-test DeepSeek English generation and plan capacity

Part of the [backlog](../backlog.md).

- **What:** Load-test increasing QPS and concurrent users with realistic per-topic fan-out plus translation, measuring completed-chapter p50/p95/p99, throughput, 429s, failure levels, tokens and cost. Evaluate dedicated or provider-owned capacity and quotas, and bound concurrency across requests: a per-instance limit plus Cloud Run --concurrency and --max-instances, which api/deploy.sh does not set today. Run against the local API with the real OpenRouter backend; creating a staging environment is not part of this work.
- **Why:** Owner decision 2026-11-13: deferred while there are no users; English generation relies on OpenRouter's performance-based routing first ([provider routing](../antsy-aphid/provider-routing.md)). Evaluation calls hit 429s from the Relace shared pool, including six of 24 serial calls on 2026-11-12 ([evaluation record](../../evals/results/2026-11-12-english-prompt-candidate-4.md#rate-limits)); four concurrent 429s did not establish a concurrency limit. `generateTopics` in `api/src/phrasebook/index.js` runs at most four topic calls per request and retries 429s within the endpoint deadline, with no limit across requests. Since 2026-11-14 a topic whose DeepSeek call is rate limited is generated by Gemini 3.5 Flash Lite instead ([limits and recovery](../../api/phrasebook.md#execution-limits-and-recovery)); it is covered by tests with stub backends only, and its latency, mixed-model cost and quality under load are unmeasured.
- **Open questions:** Latency and error targets, QPS and concurrent-user levels, and a spending cap for the test.
- **Done when:** A load test meets agreed latency and error targets, and API operations records the capacity limits.

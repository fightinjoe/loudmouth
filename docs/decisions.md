# Decisions

Product and architecture decisions that the code alone does not explain. Rubric decisions stay in the [rubric's decision log](evals/rubric.md#decision-log). Format and lifecycle: [wiki conventions](wiki.md#ledgers).

| 2026-11-15 | adopted    | English-generation list lengths: the provider response schema caps each list at the size prompt R4 asks for (three Word families of six, at most eight Things to say, four exchanges of up to four turns, ten example lines), and the parser never trims. Counts above `PHRASEBOOK_COUNT_LIMITS` are kept with `count-overrun` flags, and the Words limit rises from 10 to 18. This replaces R4's rule of keeping up to 24 Words and trimming above it. Two turns in a row by one speaker stay valid with a `speaker-repeated` flag ([POST /phrasebook](api/phrasebook.md#model-tasks-and-raw-authoring-output), [card schema](card-schema.md#content-types)). | |
| 2026-11-14 | adopted    | `/phrasebook` English generation keeps DeepSeek v4.1 Flash as the primary model and uses Gemini 3.5 Flash Lite only for topics whose DeepSeek call is rate limited. Both run the same prompt (candidate R4, usefulness first) and the same enforced reply schema. Blind reviews preferred DeepSeek over Flash Lite on that prompt, mainly on coverage, and the owner confirmed it on specific topics such as surfing and meeting in-laws ([evaluation record](evals/results/2026-11-14-english-prompt-candidate-r4.md)). It supersedes the 2026-11-13 no-fallback decision; the owner kept it on 2026-11-15 when it met OpenRouter performance routing, under which a 429 means no DeepSeek provider could take the call. |                                                     |
| 2026-11-14 | superseded | English phrasebook generation has no Gemini Flash Lite fallback: its output does not meet the quality bar. DeepSeek availability relies on OpenRouter's provider routing and fallbacks across DeepSeek providers. Adopted 2026-11-13; superseded by the rate-limit fallback. | |
| 2026-11-13 | adopted    | The API ships with three moderate `npm audit` findings in one chain: `uuid` 8.3.2 ([GHSA-w5hq-g745-h8pq](https://github.com/advisories/GHSA-w5hq-g745-h8pq)) via `cloudevents` 10.0.0 via `@google-cloud/functions-framework` 5.0.5. No upstream fix exists; cloudevents calls only `uuid.v4()` without a buffer, and the advisory affects v3/v5/v6 with a caller-supplied buffer. npm's only fix is a downgrade to functions-framework 2.0.0. Revisit when cloudevents updates `uuid`. |                                                     |
| 2026-11-13 | adopted    | Node.js 24 is the single runtime: the root `.nvmrc`, `engines` `24.x` in `api/src` and `web/app`, CI `setup-node` reading `.nvmrc`, and the Cloud Run `nodejs24` base image in `api/deploy.sh`.                                                                                                                                                                                                                                                                                         |                                                     |
